Fixture App は Core NFC を通してタグと通信するた
め、チップが動作するのは、iOS が公開しているタ
グタイプのいずれかとして応答する場合だけです。
ISO 14443A 上の Type 2、ISO 7816 上の Type 4、
ISO 15693 上の Type 5 のいずれかです。独自プロト
コルでしか応答しないチップは、識別子だけが表示
され、それ以上のことはできません。

以下の結果はすべて、iOS 18.2 が動作する iPhone 13
と iPhone 15 Pro で、3 社から仕入れた空のタグに対
して測定したものです。「読み取り」は、追加の設
定なしにスキャンシートがタグから NDEF メッセー
ジを取り出せることを指します。「書き込み」は、
書き込みシートが新しいメッセージを書き戻し、そ
の後の空きバイト数を報告できることを指します。
ユーザーメモリは NDEF メッセージが占められる領
域で、ダイ上の総メモリより常に小さくなります。

::include[legend]

:::table[iOS 18.2 で測定した、チップ別の Core NFC 対応状況]
| チップ | 型番 | 読み取り | 書き込み | ユーザーメモリ（バイト） |
| :--- | --- | :---: | --- | ---: |
| NTAG213 | `NT2H1311` | ✅ | ✅ | 144 |
| NTAG215 | `NT2H1511` | ✅ | ✅ | 504 |
| NTAG216 | `NT2H1611` | ✅ | ✅ | 888 |
| [NTAG424 DNA](https://example.com/chips/nt4h2421gx) | `NT4H2421Gx` | ✅ | ⚠️ | 416 |
| MIFARE Ultralight EV1 | `MF0UL1101` | ✅ | ✅ | 48 |
| MIFARE Ultralight C | `MF0ICU2` | ✅ | ⚠️ | 144 |
| ICODE SLIX2 | `SL2S2602` | ✅ | ⚠️ | 316 |
| [MIFARE DESFire EV3](https://example.com/chips/mf3d8x3) | `MF3D8X3` | ⚠️ | ❌ | — |
| MIFARE Classic 1K | `MF1S503x` | ❌ | — | — |
:::

## 注意点の意味

「書き込み」列の ⚠️ は、そのチップが追加の手順
を経てはじめて書き込みを受け付けるという意味で
あり、書き込みが始まったあとの動作が不安定だと
いう意味ではありません。

NTAG424 DNA は NDEF ファイルが AES 認証で保護さ
れた状態で出荷されるため、書き込みシートは内容
を変更する前にアプリケーションキーを求めます。
Ultralight C はカウンターより上のページで 3DES を
使い、「設定」「詳細」「タグのキー」にキーを貼
り付けないかぎり、Fixture App はロックバイトより
下に書き込みます。ICODE SLIX2 は ISO 15693 で応
答し、メッセージを 4 バイトのブロック単位で格納
するため、空きバイト数は 4 ずつ減ります。

DESFire EV3 は読み取りだけができます。端末は
NDEF アプリケーションを選択して中身を読めます
が、ファイルの作成やサイズ変更には、利用者に持
たせるつもりのないキーが必要です。そのため書き
込みボタンは暗いままで、「このタグは iPhone では
読み取り専用です」と表示されます。MIFARE
Classic 1K はまったく読み取れません。iOS は識別
子を返してそこで止まり、スキャンシートはエラー
2001「タグが NDEF に準拠していません」を報告し
ます。どちらのチップもメモリの列に数値がありま
せん。DESFire ではファイルの作成時にサイズが決
まり、Classic には測定できる NDEF ファイルがない
からです。

## 一覧にないチップの場合

スキャンシートに表示されるタグ識別子と、パッケ
ージに印字された表記を
[docs@example.com](mailto:docs@example.com) までお
送りいただければ、こちらで検証します。この一覧
にあるチップでも、金属板の入ったケースや決済カ
ードの背後では失敗することがあります。それにつ
いては
[スキャンできないとき](../guide/troubleshooting.md)
で扱っています。
