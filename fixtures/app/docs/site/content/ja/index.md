Fixture App を使うと、iPhone がタグのリーダー兼
ライターになります。Apple がサードパーティ製ア
プリに公開している NFC ハードウェア上で動作する
ため、スキャンシートを開いた状態で一度に 1 枚の
タグだけを扱えます。

## Fixture App でできること

端末の上端をタグに当てると、タグ上の NDEF メッ
セージがデコードされます。そこからレコードをそ
の場で編集したり、タグを新しいメッセージで上書
きしたりできます。アップロードは一切行わず、ス
キャン履歴もアプリを閉じると残りません。

リーダーは次のペイロードを解釈します。
- テキストレコード（タグが宣言する言語コード付き）
- URI レコード（`tel:` や `mailto:` のショートカットを含む）
- Android 端末が書き込んだ Wi-Fi ハンドオーバーレコード
- vCard ペイロード（連絡先カードとして表示）

書き込みは*破壊的*な操作です。アプリは NDEF メ
ッセージに追記するのではなく全体を置き換えるた
め、**書き込み**をタップした時点で、それまでタ
グに入っていた内容は失われます。ロックされたタ
グも読み取りはできますが、ライターは成功を報告
せず `Tag is permanently locked` で停止します。

## 必要なもの

対応ハードウェア：iPhone 7 以降、iOS 16 以降。\
対応タグ：NDEF フォーマット済みの ISO 14443
Type A チップ。

[チップ対応表](reference/chip-support.md)には、リ
ーダーで検証済みのすべてのチップと、それぞれの
書き込み可能なメモリ容量を掲載しています。
NTAG213 の容量は 132 バイトで、短い URL を入れる
と、ほとんど余りは残りません。

:::note[バックグラウンドスキャン]
iOS がバックグラウンドのアプリにタグを渡すの
は、そのタグにアプリの associated domain と一致す
る URL レコードが入っている場合だけです。それ以
外は、スキャンシートをフォアグラウンドで開いて
おく必要があります。
:::

::include[safety-note]

## 次に読むもの

まずは[最初のタグをスキャンする](guide/first-tag.md)
から始めてください。空の NTAG215 に対する 1 回の
読み取りと 1 回の書き込みを扱っています。タグが
まったく読み取れない場合は、先に
[必要なもの](#what-you-need)を確認してください。
失敗の多くはタグの故障ではなく、リーダーが扱え
ないチップが原因です。

[docs@example.com](mailto:docs@example.com)
